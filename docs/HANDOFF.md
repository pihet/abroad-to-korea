## 0. 주제 (제안서 기준)

**해외 여행지 사진으로 찾는 분위기 유사 국내 여행지 추천 웹 서비스**
- 사용자가 해외 여행지(사진)와 여행 월을 고르면, 기후·장소 구성·지형 특징 벡터의 유사도(kNN)로 국내 시군구를 추천
- 좋아요/싫어요 피드백으로 특징 가중치를 밴딧 방식으로 조정
- 원본 제안서: `프로젝트 주제 제안서.docx` (팀 공유 드라이브)

**종합 판정: 조건부 진행 가능.** 주요 리스크 2개(아래 3장)에 대한 대응을 설계에 반영해야 한다.

> **2026-10-02 프로토타입 후 갱신 (상세 7장):**
> - 분위기 추천의 주 신호는 **CLIP 사진 유사도**다 (vote100 Hit@10 8/11). 기후·지형·장소 정형 특징은 약하다 (최고 Hit@10 4/11, 기후 단독 0/11)
> - **혼잡도(방문자 수) 예측**이 정답이 명확한 ML 구성 요소로 추가됐다 (연휴 관련일 오차 28.9% → 17.7%)
> - 따라서 위 설명(기후·장소·지형 kNN 중심)은 "**CLIP 사진 유사도 + 혼잡도 예측 + 피드백 밴딧** 중심, 기후·지형·장소는 보조"로 읽는다

## 2-1. ML 구조 (2026-10-02 팀 논의 반영, 초안)

> 핵심 표현: **"유사도 검색 + 특징 가중치 학습 + 컨텍스트 밴딧"**. 군집·분류는 핵심이 아니라 보조.

```
[입력] 해외 여행지(사진) + 여행 월 + 우선순위(덜 붐비게/가깝게/선호 지역/관심사)
 ① 특징 추출: CLIP 이미지 임베딩(주 신호) / 기후(해당 월) / 장소 구성(백분위, 출처 미결) / 지형(고도·기복·해안·녹지)
 ①' 혼잡도 예측: 여행 날짜 × 시군구 → 예상 외지인 방문자 수 → "덜 붐비게" 점수
 ② 유사도 검색(kNN) → 국내 후보 Top-N
 ③ 점수 결합: score = Σ w_i · 유사도_i + Σ v_j · 우선순위_j
 ④ 밴딧: 좋아요/싫어요 보상으로 ③의 가중치를 사용자별 조정
```

| 구성 | 역할 | 학습 | 데이터 |
|---|---|---|---|
| CLIP (사전학습) | 사진 분위기 특징 추출 | ❌ (추론만) | TourAPI 사진 중 공공누리 1·3유형 11,651장 (프로토타입에서 11,353장 사용, 298장 다운로드 실패) |
| 혼잡도 예측 (기준값 B1 + 보정 회귀, 추후 LightGBM 비교) | "덜 붐비게" | ✅ | 방문자수 API 2018-01~2026-08. 학습 2019~2024 / 검증 2025 / 테스트 2026 |
| kNN | 후보 검색 | ❌ | 위 특징 벡터 |
| 특징 가중치 학습 | **ML 핵심**: 기후/장소/사진/지형 반영 비중 | ✅ | 약한 정답 쌍 (현재 평가용 19개, `data/external/ground_truth_pairs.csv`) |
| 컨텍스트 밴딧 (Thompson Sampling / LinUCB) | 개인화 | ✅ 온라인 | 피드백. 실사용자 없으므로 **정답 쌍 기반 가상 사용자 시뮬레이션** |

- 분류(보조): CLIP zero-shot 텍스트 프롬프트("사찰", "해변", "설산" 등)로 사진 태깅 → 추천 근거 표시. 별도 학습 없음
- 군집(선택): 국내 지역 유형 묶기(해안휴양/산악/고도시) → 탐색 UI·설명용. 핵심 파이프라인에는 넣지 않음
- 용어: "강화학습" 대신 **컨텍스트 밴딧**으로 표기 (상태 전이 없음)

### 평가 계획 (ablation, 지표 Hit@5 / Recall@k, leave-one-out)

1. 랜덤 → 2. 기후만 → 3. 기후+장소 → 4. +CLIP → 5. +가중치 학습 → 6. +밴딧(시뮬레이션, 피드백 누적에 따른 학습 곡선)

- 2026-10-02 실측 반영: 2단계(기후만)는 Hit@10 0/11로 랜덤과 차이가 없었다. 발표용 비교 순서는 "랜덤 → 정형 특징(기후+지형+장소) → CLIP → CLIP+정형 → +가중치 학습 → +밴딧"으로 바꾸는 것을 권장

- 정답 쌍이 적으므로 학습 가중치는 4~5개로 제한 (과적합 방지)
- 건축 모방 쌍(쁜띠프랑스 등)은 평가에서 제외
- CLIP 효과: **확인됨.** 사진 특징이 P3(기후·지형·장소)보다 정답 쌍을 훨씬 잘 맞힌다. 수치와 편향은 7장 P2 참고

  - 2024 내부검증 (2019·2023 학습): B1 10.57% / 연휴 21.18% → 개선 8.73% / 13.14%
  - 두 해 모두 B1 대비 전체 약 14~17%, 연휴 관련일 약 27~38% 오차 감소
- 판단: **통과.** 두 해 내부검증에서 일관되게 개선됐다
  - 단, 같은 2025로 여러 방식을 본 뒤 고른 것이라 2025 수치는 약간 낙관적이다
  - 최종 성능은 2026 테스트로 한 번만 잰다

### P3. 분위기 유사도 (정답 쌍 기반 검색)
- 질의 11개(해외) → 국내 230개 시군구 순위, 정답 시군구가 상위 k에 있는지 (`use_for_eval=1` 19행을 해외지별로 묶음)

## 10. P1 재현 명세 (Aside 원본 계산의 정확한 설정, 2026-10-02)

> 7장 P1을 쓸 때 코드와 특징 정의를 남기지 않아 재현이 안 됐다. 아래가 Aside REPL에서 실제로 돌린 설정 전부다. (Aside 쪽 실수: 코드 미보존)

### 공통
- 대상: `touDivCd=2`(외지인)만. 2018-01-01~2026-08-31 전 기간 결측 없는 시군구 258개
  - 전남·광주 2026-07 이후 신코드(12xxx)는 **이름이 같은 구코드(46xxx, 29xxx)에 더해서** 병합
  - 인천 개편 구(제물포·영종·서해·검단 등)와 부천 구 등 결측 있는 코드는 제외
- 모델: ridge, λ=1, **표준화 없음**, 절편은 벌점 제외, 정규방정식 직접 풀이
- 지표: WAPE = Σ|ŷ−y| / Σy (원 단위로 되돌린 뒤), medAPE = |ŷ−y|/y의 중앙값
- 분할: 목표 시점 연도 기준. 학습 2019~2024 / 검증 2025

### 월 단위 (WAPE 5.6%)
- a[t] = 시군구 월 합계 외지인 수, 예측 시점 o = t−2 (2개월 전)
- 특징 19개:
  1. log1p(a[t−12])
  2. log1p(a[o])
  3. log1p(a[o−1])
  4. yoy = log((a[o]+a[o−1]+a[o−2]+1) / (a[o−12]+a[o−13]+a[o−14]+1))
  5. log1p(a[t−24]) — t<24면 a[t−12]로 대체
  6. covid = 목표 연도가 2020 또는 2021이면 1
  7. covidLY = 목표 연도−1이 2020 또는 2021이면 1
  8~19. 목표 월 원-핫 12개
- 목표값: log1p(a[t]), 예측은 expm1
- 행: a[o−14]가 있는 t부터 (첫 목표월 2019-05). 학습 17,544행 / 검증 3,096행
- **학습에서 코로나 기간을 빼면 7.2%가 나왔다** (같은 표의 "ridge 코로나 제외" 행). 재현값 7.2%와 정확히 같으므로 재현 쪽이 2020~2021 행을 학습에서 뺐을 가능성이 크다. covid·covidLY 플래그를 넣고 2020~2021 행을 **포함**해서 학습해야 5.6%가 나온다
- 기준값 B1 = a[t−12] × exp(yoy)

### 일 단위 (전체 WAPE 8.7%, 연휴 관련일 17.7%)
- 구조: **직접 예측이 아니라 B1 위의 잔차 보정** (직접 예측 ridge는 10.7%로 B1보다 나빴음)
  - B1 = a[i−364] × exp(trend), trend = log((Σ_{k=i−58}^{i−31} a[k] + 1) / (Σ a[k−364] + 1)) — 예측 시점 30일 전까지의 28일 증감
  - 목표값 = log1p(y) − log1p(B1), 예측 = expm1(log1p(B1) + ŷ)
- 공휴일 집합: Nager.Date 2017~2026 + 수동 추가 {20250127, 20250506, 20250603, 20180613, 20220309, 20220601, 20240410, 20241001, 20231002, 20200415, 20200817} − {20250717}
  - 9-2에서 밝혔듯 이 집합은 2018~2024 제헌절을 잘못 포함하고 2021 대체공휴일 3일이 빠져 있다. 정식 CSV로 바꾸면 수치가 달라질 수 있다
- off(j) = 토·일 또는 공휴일
- base 10개: h(당일 공휴일), pre(다음날 공휴일), post(전날 공휴일), lyH(364일 전 공휴일), off(당일), offLY(364일 전), longWk(off(i)∧off(i−1)∧off(i+1)), longLY(같은 정의를 364일 전에), off−offLY, longWk−longLY
- s = 시군구 주말민감도 = 2019년 휴무일 평균 log1p(y) − 평일 평균 log1p(y) (학습 기간 안에서만 계산)
- 특징 39개 = base 10 + base×s 10 + 요일 원-핫 7 + 월 원-핫 12
- 행: i ≥ 422 (trend 창이 데이터 범위 안). 학습 550,830행 / 검증 94,170행
- 연휴 관련일 = h ∨ lyH ∨ longWk ∨ longLY (검증 11,094행)
- 재현 9.7%는 B1(9.9%)보다는 낫다. **연휴 관련일 부분집합 수치도 같이 비교할 것**. P1의 주장은 전체 평균이 아니라 연휴 예측 개선(28.9% → 17.7%)이었다

### 판단에 대한 의견

### 11-3. CLIP + 사용자 카테고리 재정렬 실험 (2026-10-02, Codex)

- 코드: `src/model/category_rerank.py`
- 결과: `data/interim/clip/eval_category_rerank.json`
- 조건: 11-1과 같은 카탈로그 평가 해외지 20곳, 국내 230개 시군구, vote100
- 실제 사용자 입력은 아직 없으므로 카탈로그의 `vibe_tags`를 선택 카테고리의 대리값으로 사용했다
- 국내 카테고리 점수는 CLIP 영어 텍스트 프롬프트와 국내 관광지 사진의 유사도로 계산했다
  - 지역별 상위 3장 점수 평균을 시군구 간 순위 백분위로 변환
  - 최종 점수 = `(1-w) × CLIP 이미지 순위점수 + w × 카테고리 순위점수`
- 국내 대응이 어려운 태그(소금사막·피오르·빙하호·산호초·세노테 등)는 억지로 매핑하지 않고 CLIP 단독으로 fallback한다
  - 평가 20곳 중 fallback은 우유니 1곳

| 선택 조건 | 카테고리 가중치 | Hit@5 | Hit@10 | Hit@20 | MRR | 중앙 순위 | 최악 |
|---|---:|---:|---:|---:|---:|---:|---:|
| CLIP 단독 | 0.0 | 11 | 14 | 18 | 0.369 | 5 | 40 |
| 대표 카테고리 1개 | 0.2 | 12 | 15 | 18 | 0.325 | 5 | 32 |
| 대표 카테고리 1개 | **0.4** | **14** | **15** | **19** | 0.366 | **4** | 37 |
| 지원 카테고리 전체 | 0.4 | 12 | 15 | 19 | 0.332 | 4 | 37 |

- 대표 카테고리 1개·가중치 0.4에서 Hit@5 11→14, Hit@10 14→15, Hit@20 18→19로 개선됐다
  - 여행지별 순위는 8곳 개선 / 6곳 악화 / 6곳 동일
  - 큰 개선: 마추픽추 40→18위, 그랜드캐니언 15→5위, 장가계 8→3위
  - 큰 악화: 친퀘테레 29→37위, 하롱베이 4→9위, 세렝게티 16→20위
- 표본이 20곳뿐이라 Hit@5 경계 통과는 개선 4곳·악화 1곳이고, 양측 정확검정으로 우연과 구분되지 않는다(`p=0.375`)
- **다양성은 악화됐다**

| 카테고리 가중치 | 상위 5에 나온 시군구 | 상위 10개 지역 비중 |
|---:|---:|---:|
| 0.0 | 137 / 230 | 38% |
| 0.2 | 113 / 230 | 41% |
| 0.4 | 103 / 230 | 43% |

- 해석: 같은 카테고리를 고른 여러 질의가 해당 범주의 대표 지역으로 함께 몰린다. 카테고리는 정확도 보조 신호가 될 수 있지만 hubness 해결책은 아니다
- 판단: **서비스 기본값으로 아직 채택하지 않는다.** 현재 후보는 “대표 카테고리 1개, 가중치 0.4”이며, 정답 해외지를 50곳 이상으로 늘린 뒤 재평가한다
- 실제 사용자 입력으로 검증한 결과가 아니므로, 이후에는 카테고리 선택 일치율과 사람이 판단한 엉뚱한 추천 비율도 별도로 측정한다

## 14. 조건 반영 2단계 추천 + 탐색 페이지 v2 (2026-10-04, Claude Code)

- 배경
  - 사진만으로는 유동량·활동·날씨를 반영하지 못한다 (사람 평가 도시형 엉뚱함 23%)
  - 참고 서비스 World Travel Index(Cost·Attractions·Safety·Infrastructure Index, 닮은꼴 찾기에 관심사·우선순위 선택)를 검토했다
  - 안전은 국내라 제외. 비용은 데이터 부족(외식비 시도 단위, 숙박 가격 없음)으로 확장 과제로 둔다
- 구조: **유사도에 섞지 않고 2단계**로 넣는다 (카테고리를 유사도에 섞은 11-3·11-6은 실패)
  1. 닮음: 서비스 기본값 상위 20곳
  2. 조건: 덜 붐비게(10월 혼잡도) / 가깝게(출발지 직선거리) / 날씨 좋게(10월 쾌적도) / 관심사(자연·역사·문화·도시·체험·휴식 관광지 수)
  - 점수 (결과 전에 고정)
    - 닮음 = 후보 20곳 안 순위의 0~1 값, 조건 = 후보 20곳 안 백분위
    - 조건 1개: 0.5·닮음 + 0.5·조건 / 조건 + 관심사: 0.4·닮음 + 0.3·조건 + 0.3·관심사
  - 축제(TourAPI 2026년 10월 257건)는 점수에 넣지 않고 정보로만 표시
- 새 데이터 (`src/collect/region_context.py`)

    - 쾌적도 = −(기온이 15~24°C 밖으로 벗어난 정도 + 0.5 × 월평균 비 온 날(1mm 이상))
  - 축제: `searchFestival2` 2026-10-01~31

- 해석: 조건 지표는 확실히 좋아지고, 원래 상위 5곳의 절반 이상이 유지되며, 새로 올라온 곳도 닮은 순 8~9위 후보다
